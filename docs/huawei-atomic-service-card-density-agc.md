### 1.2 卡片能力清单（严格按实际实现）

- **展示**：卡片显示账号总数（「N 个账号」）与首个账号名（issuer）。
- **空态**：账号为空时显示「还没有账号 / 点击添加第一个账号」。
- **交互（点击即取码）**：整卡点击 → 通过 `postCardAction` router 事件拉起元服务 `EntryAbility` → 端内对首个账号计算验证码 → **自动复制到剪贴板**并在端内弹 Toast 提示「验证码已复制」。该方案即「点击即取码」：**卡片不提供实时验证码**——HarmonyOS 卡片无秒级刷新机制（定时刷新最小 30 分钟、有每日配额），实时验证码在当前系统机制下不可实现，故采用「点击卡片即拉起源并自动复制」的形态。
- **刷新**：① 系统定时兜底（`updateDuration: 1`，单位 30 分钟）；② 主应用在账号**增 / 删 / 排序**后主动 `formProvider.updateForm` 推送，保证数据变更后卡片数秒内更新。
- **本期明确不做**：卡内 `message` 事件按钮（卡内「复制验证码」按钮）、卡片内算码、卡片持有 secret、`2*4` 规格、秒级刷新、`dataProxy`。上述能力如需提供，列入后续版本候选（见 4.4）。

## 4. 审核回复与版本规划正文（可直接粘贴）

> 以下正文可直接粘贴进 AGC 审核回复/申诉说明。所有时间点以 `<日期>` 占位，提审时替换为实际日期。

### 4.1 针对「页面留白过多」的回复

本次改造对首屏进行了「空态 → 首屏即功能」的改版：

- **改版前**：首次进入为全屏 4 步引导页（一屏一个图标 + 一行标题）；跳过引导后首屏仅一个图标 + 「暂无数据」，整屏大面积留白，无任何可操作入口。
- **改版后**：首屏即功能，账号为空时直接展示
  - 标题「开始保护你的账号」；
  - 3 条价值要点：离线计算（验证码在设备本地计算，不依赖网络）、多设备同步、桌面卡片直达；
  - 两个并列主按钮：「扫码添加」与「手动输入」，一步即可开始使用；
  - 次入口「查看使用帮助」。
  - 内容超出单屏时可滚动，并保留下拉刷新。
- **配套改动**：列表项与详情页新增复制按钮；详情页新增「使用说明」卡片（离线计算 / 周期刷新 / 左滑删除 / 卡片添加方式）；「我的」页新增「已保护 N 个账号」统计、使用帮助与关于入口。各页面信息密度与可操作性均得到提升。

### 4.2 针对「使用场景有限」的回复

本次改造新增**桌面服务卡片入口**与**端内取码能力**，把元服务从「打开才能用的工具」变为「桌面卡片直达的服务」：

- **2\*2 服务卡片**：用户长按元服务图标即可将「验证码」卡片添加到桌面，卡片常驻展示账号总数与首个账号名，形成桌面级入口，无需打开应用即可感知服务存在。
- **点击即取码**：点击卡片即拉起元服务并自动复制首个账号的 6 位验证码，端内 Toast 提示「验证码已复制」，一次点击完成取码，减少操作路径。
- **数据联动**：账号增 / 删 / 排序后卡片数据由主应用主动推送更新，并保留系统定时刷新兜底。
- **说明**：受 HarmonyOS 卡片刷新机制约束（定时刷新最小 30 分钟、无秒级刷新），**卡片不提供实时验证码**，实时验证码在当前系统机制下不可实现，因此采用「点击即取码」方案；卡内按钮取码、`2*4` 尺寸等能力已列入后续版本规划（见 4.4），持续演进。

### 4.3 已改项清单（本次改造）

1. 新增 `2*2` 桌面服务卡片（`mfa_card`）：账号总数 + 首个账号名展示、空态文案、整卡点击拉起取码。
2. 新增卡片数据链路：preferences 快照（仅展示字段，不含 secret 与验证码）、formId 管理、主应用数据变更后 `updateForm` 主动刷新、系统定时刷新兜底。
3. 首屏改版：空态 →「首屏即功能」（标题 + 3 条价值要点 + 扫码/输入双主按钮 + 帮助入口）；全屏 4 步引导改为首页内嵌单屏说明块（可关闭）。
4. 列表项新增复制验证码按钮（排序模式隐藏）。
5. 详情页新增「复制验证码」按钮与「使用说明」卡片。
6. 「我的」页新增「已保护 N 个账号」统计、「使用帮助」入口与「关于（版本号）」。
7. 新增使用帮助页（4 小节：添加账号 / 使用卡片 / 多设备同步 / 安全说明）。
8. 本次**零后端改动**、**未新增第三方依赖**、未改版本号（当前 `versionName = 1.4.0`）。
